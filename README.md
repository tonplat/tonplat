# ТонПлат — обновление сайта (Zapnoty + MAX + cookie-уведомление)

Этот файл входит в **небольшой архив исправлений** к ранее скачанному полному архиву `tonplat-ready-for-publication.zip` (118 файлов). Распакуйте файлы исправлений с заменой в корень сайта / репозитория. Не требуется загружать повторно фотографии и `menu-data.js`.

## Что изменено
- При первом открытии главной страницы видна плашка «Мы используем файлы cookie» с выбором. Технический cookie `tonplat_cookie_choice_v2` живёт до 180 дней; корзина между посещениями — только после разрешения.
- Формы отправляют заявки в **Zapnoty Forms** по HTTPS; маршрут в **MAX** задаётся в кабинете Zapnoty. Убрана устаревшая ручная отправка через WhatsApp/Telegram.
- Заявка уходит формальной сметой: номер и дата (`СМ-ГГГГММДД-ЧЧММ`), реквизиты исполнителя, построчный состав корзины (до 40 строк + свернутый остаток) и итог. Единая кнопка «Скачать смету (DOCX)» в корзине и «Сохранить смету (DOCX)» после отправки собирает Word-документ с таблицей, реквизитами и подписью прямо в браузере (ZIP+WordprocessingML, без библиотек). В формах есть необязательное поле «Telegram (по желанию)» — попадает в заявку и в смету — ред. 19.11.2026.

## Смета файлом в MAX (ред. 19.11.2026)

Публичная форма Zapnoty принимает только JSON, поэтому файл доставляется двухступенчато:

1. Сайт генерирует DOCX сметы в браузере и кладёт его в заявку полями `docx_b64` (base64) и `docx_name`.
2. Workflow `github-actions/zapnoty-estimate-to-max.yml` (копировать в `.github/workflows/` репозитория сайта) раз в 5 минут забирает новые заявки через `GET /v1/forms/{form_id}/submissions`, загружает DOCX в приватное хранилище Zapnoty (`POST /v1/agent/media`, multipart) и отправляет подписчику в MAX сообщение с документом: `POST /v1/send` с `media: {type: "document", media_id: …}`. Файл не публикуется в открытом виде — адрес выдаётся только в момент отправки.

Секреты GitHub (Settings → Secrets and variables → Actions): `ZN_API_KEY` (ключ проекта `zn_live_…`, кабинет → «API и MCP»), `ZN_SUBSCRIBER_MAX` (`sub_…` — subscriber_id получателя: кабинет → «Подписчики» → deep-link MAX → открыть и нажать «Старт», либо `GET /v1/subscribers`), опционально `ZN_AGENT_KEY` (`agtk_…`, если загрузку медиа не примет ключ проекта). Курсор обработанных заявок хранится в actions/cache. До подключения workflow в MAX приходит смета текстом (маршрут «Всегда») — после подключения добавляется файл.
- Исправлены `privacy.html` (переименована в «Политику в отношении обработки персональных данных»), `consent.html`, `cookies.html`, `terms.html` — ред. 08.11.2026: полные реквизиты оператора по карточке предприятия (ООО «Тон Плат», ИНН/КПП/ОГРН, юридический и фактический адреса), обработчики Zapnoty и MAX по поручению, сроки и права субъектов, таблица cookie по именам, условия отмены/доставки/претензий и оговорка об отсутствии публичной оферты.
- Реквизиты на сайте унифицированы по карточке: телефон 8-927-605-84-88 (старый +7 960 812-13-33 убран, включая Telegram-ссылку), домен — `https://тонплат.рф/` (canonical, og:url, JSON-LD, config.js).
- Нумерация не показывается также в карточке подробностей блюда.

## Без обязательной настройки отправка НЕ работает

1. В кабинете **https://app.zapnoty.ru/** создайте **Forms / Форму**. В `allowed_origins` разрешите боевой домен `https://тонплат.рф` (в punycode: `https://xn--80avfdgpf.xn--p1ai`, без пути) и на переходный период служебный домен GitHub Pages; настройте маршрут получателя в MAX. Получите публичный `form_id` — это **UUID** вида `123e4567-e89b-42d3-a456-426614174000`.
2. В маршрутах (routes) этой формы укажите **получателя в MAX** и проверьте, что этот бот/аккаунт действительно может получать сообщения.
3. Откройте `config.js` и укажите идентификатор: `zapnoty: { formId: "ВАШ_UUID_ФОРМЫ", endpointBase: "https://api.zapnoty.com/f/" }` (уже есть структура; замените только пустое значение). Валидатор на сайте принимает **только UUID** (8-4-4-4-12 hex): строка иного вида не отправляется, посетитель видит человеческое сообщение с телефоном и Telegram вместо технической ошибки. **API-ключи `zn_...` не вставляйте в сайт**. Публичный endpoint формы не требует секретного API-ключа.
4. Опубликуйте сайт по HTTPS и отправьте **тестовую заявку**. Проверьте факт появления в кабинете Zapnoty и получение уведомления в MAX. Без этого теста нельзя считать доставку готовой.
5. Если Zapnoty выдаст для вашей формы конкретный публичный URL, сверяйте его с `https://api.zapnoty.com/f/<form_id>`; при различии обратитесь к актуальной документации Zapnoty.

## Что ещё обязательно проверять владельцу бизнеса

Публикация документов на сайте **не означает автоматическое соответствие законодательству**. В частности, до запуска коммерческой обработки нужно проверить точность реквизитов/адреса, уведомление Роскомнадзора по статье 22 Закона №152-ФЗ, внутренние документы, учёт согласий, назначение ответственного, фактические сроки и место хранения заявок, договоры и поручения обработки с Zapnoty/MAX, локализацию баз данных граждан РФ, отсутствие незаконной трансграничной передачи, защиту аккаунтов и процедуру обработки запросов/отзыва согласия. При изменении cookies или подключении аналитики обновите механизм согласия и документы.

Ссылки на нормы: https://www.consultant.ru/document/cons_doc_LAW_61801/ (ФЗ №152); https://zapnoty.ru/features/forms (Zapnoty Forms). Для продажи/заказа дистанционно проверьте также требования законодательства о защите прав потребителей и информацию об изготовителе/товаре.

## Подключение заявок в MAX (ред. 19.11.2026)

Схема: сайт → публичный эндпоинт Zapnoty `POST https://api.zapnoty.com/f/<form_id>` (без API-ключа, защита через allowed_origins) → маршрут формы → ваш аккаунт в мессенджере MAX через бота Zapnoty.

1. **Привязка аккаунта MAX.** В кабинете Zapnoty (app.zapnoty.ru) в разделе каналов Telegram/Max возьмите дип-ссылку бота Zapnoty для MAX, откройте её в мессенджере MAX и нажмите «Начать» (по правилам MAX бот пишет первым только после сообщения пользователя). После этого ваш аккаунт виден в кабинете как получатель. Отдельный MAX-бот и токен с dev.max.ru для этой схемы не нужны.
2. **Форма и домены.** Формы → Создать. В allowed_origins внесите `https://тонплат.рф`, `https://xn--80avfdgpf.xn--p1ai` и (временно) `https://ch1lov1c.github.io` — без пути, иначе origin-check вернёт ошибку.
3. **Маршрут в MAX.** В настройках формы добавьте маршрут доставки в Max на привязанный аккаунт; при желании добавьте email-маршрут (всего до 40 маршрутов на форму).
4. **Код.** Скопируйте публичный form_id (UUID вида 8-4-4-4-12) и вставьте его в `config.js` в строку с `formId:` (блок `zapnoty`, помечен комментарием «ОБЯЗАТЕЛЬНО»). Это единственное место в исходниках; после правки для одностраничной сборки выполните `python3 make_single.py`, для публикации файлами достаточно закоммитить `config.js`.
5. **Тест.** Отправьте тестовую заявку с опубликованного сайта: сообщение должно прийти в MAX и появиться в списке заявок кабинета (доступен CSV-экспорт). Без этого теста доставку считать не настроенной.

Важно: API-ключи `zn_...` и токены MAX-бота в клиентский код не помещаются никогда — они нужны только для серверных вызовов Zapnoty (`POST /v1/send` и т. п.), которых в этой схеме нет.

## Скорость загрузки и состав файлов (ред. 19.11.2026)

- `index.html` — БОЕВАЯ лёгкая версия: HTML ~60 КБ, все картинки и скрипты отдельными файлами с ленивой загрузкой (`loading="lazy"`, `decoding="async"`), hero-кадр с `fetchpriority="high"` и preload, preconnect к api.zapnoty.com. Браузер кэширует ассеты между визитами, первая отрисовка — мгновенно.
- `index-offline.html` — автономная копия (все ассеты встроены, ~8,6 МБ) только для офлайна, письма или архива; для хостинга НЕ использовать.
- Фирменный прелоадер «клещ с паром» (inline-стили в head + SVG-анимация) показывается до загрузки ассетов и плавно исчезает по событию load или через 4 с; логика скрытия в `app.js`, уважает prefers-reduced-motion.
- Если Zapnoty отклоняет запрос из-за allowed_origins, форма показывает понятную подсказку про домены вместо общей ошибки.
